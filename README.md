# DocMind

DocMind is a document question-answering app. Users upload documents to a chat, ask questions in Arabic, French or English, and receive answers grounded in their files, with the source passages shown next to each reply.

## Features

- Cookie-based authentication (register, login, logout)
- Separate chats, each with its own documents and message history
- Document upload with processing status (pending, processing, completed, failed)
- Hybrid retrieval: dense vector search (pgvector) combined with full-text search
- Multilingual embeddings (bge-m3), so questions and documents can be in different languages
- Answers generated by an LLM using only the retrieved context
- Sources stored per answer, with file name, page number and similarity score (only chunks above 0.5 similarity are kept)
- Provider and response latency recorded on every answer
- Markdown and LaTeX math rendering, one-click copy, auto-scroll, light and dark mode

## Database

The full schema is in `server/db/schema.sql` and is safe to re-run.

| Table | Purpose |
|---|---|
| `users` | Accounts: username, email, password hash, display name, avatar |
| `chats` | One conversation per row, owned by a user |
| `documents` | Uploaded files with language, page count and processing status |
| `chunks` | Text segments of each document with a 1024-dimension embedding and a generated text-search column |
| `messages` | User and assistant messages, with latency and the model that answered |
| `sources` | The chunks used for each assistant message, with score and rank |

Relationships: a user owns chats, a chat has documents and messages, a document has chunks, and each assistant message links to its chunks through `sources`. Deleting a parent row cascades to its children.

## Getting started

### Prerequisites

- Node.js 20 or later
- Python 3.12
- PostgreSQL 16 with the `pgvector`, `pgcrypto` and `citext` extensions (the Docker setup includes them)
- A Gemini API key

### 1. Database

```bash
cd server
docker compose up -d
```

If you use your own PostgreSQL instance, apply the schema manually:

```bash
psql "$DATABASE_URL" -f schema.sql
```

### 2. Backend

```bash
cd server
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Create `server/.env`:

```env
DATABASE_URL=postgresql+psycopg2://docmind:docmind@localhost:5432/doc_mind_db

JWT_SECRET_KEY=DIOJRI34U5834KJ5IOJ6LKL
JWT_ALGORITHM=HS256

ACCESS_TOKEN_EXPIRE_MINUTES=3600
REFRESH_TOKEN_EXPIRE_DAYS=30

FRONTEND_URL=http://localhost:3000

CLOUDINARY_CLOUD_NAME=value
CLOUDINARY_API_KEY=value
CLOUDINARY_API_SECRET=value


COHERE_API_KEY=cohere-api-key

ENVIRONMENT=development

GEMINI_API_KEY=api-key
GEMINI_MODEL=gemini-2.5-flash
# Database and authentication settings: see config/config.py
```

Run the API:

```bash
uvicorn main:app --reload
```

Interactive API documentation is available at `http://localhost:8000/docs`.

### 3. Frontend

```bash
cd client
npm install
```

Create `client/.env.local`:

```env
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Run the app:

```bash
npm run dev
```

Open `http://localhost:3000`.

## How a question is answered

1. The question is embedded with bge-m3.
2. The most relevant chunks of the chat's documents are retrieved.
3. Chunks with a similarity of 0.5 or lower are discarded.
4. The remaining chunks are sent to the LLM as context, with instructions to answer only from that context.
5. The answer is saved together with its sources, latency and model name.
